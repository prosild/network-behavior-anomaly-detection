# 공격 후보 하나·정상 비교 하나의 관측 의미

- 작성일: 2026-11-03
- 단계: 0. 최종 설계 10절의 완료 기준 "공격 후보 하나·정상 비교 하나의 관측 의미"에 해당한다.
- 범위: 공식 일정, 최종 설계, 기존 측정 기록만 사용했다. 새 데이터는 열람하지 않았다.
- 아래의 "예상"은 가설이다. 확인은 단계 1의 근거 검토(후보당 45분, 대표 구간 최대 3개)에서 한다.

## 1. 공격 후보: 수요일 DoS Slowloris

| 항목 | 내용 | 근거 수준 |
| --- | --- | --- |
| 출처 | CIC 공식 일정. 2017-07-05 09:47\~10:10, 현지 시각 | 일정 |
| 시간 후보(UTC) | 12:47\~13:10 | 기존 측정에서 일정 시각이 PCAP 시각과 UTC-3으로 맞았다. 이 후보에 대해서는 미확인 |
| 상대 | `172.16.0.1`. CIC의 NAT 주소다. 공격자 실체가 아니며 점수화 자산도 아니다 | 설계 3.2절 |
| 대상·역할 | `192.168.10.50`, `responder` | 일정. 로그 미확인 |
| 에피소드 상태 | 아직 없음. 단계 1에서 `confirmed`·`uncertain`·`unsupported` 중 하나로 정한다 | — |

**공격 원리:** 웹 서버에 HTTP 연결을 많이 열어 둔다. 요청 헤더를 끝내지 않고 조금씩 보내며 연결을 붙잡아, 서버의 연결 자원을 고갈시킨다.

**conn에서 보일 것으로 예상하는 것** (`.50`의 responder 창 기준):
- 같은 상대 주소에서 온 연결 수 증가. 상대 주소 수는 크게 늘지 않는다.
- 연결당 바이트가 작고 지속시간이 길다.
- **기록 지연:** 연결이 끝나야 conn이 기록된다. 그래서 공격 중의 창에는 기록이 적다. 공격이 끝나거나 서버가 연결을 끊을 때 기록이 몰릴 수 있다. 이 경우 `_write_ts` 기준 후보 창은 공식 일정보다 늦게 나타난다.
- 연결 상태 분포가 평소와 다를 수 있다. 어떤 상태가 늘지는 확인 전이라 단정하지 않는다.

**conn으로 보이지 않는 것:**
- HTTP 헤더를 끝내지 않았다는 사실 자체. 패킷 내용이 없다. `http.log`는 모델 입력이 아니다.
- 서비스 거부의 성공 여부. 다른 클라이언트의 연결 실패가 간접 근거가 될 수 있지만 가설이다.
- 공격자의 실제 주소. NAT 뒤에 있다.

**불확실성과 단계 1에서 확인할 것:**
1. 실제 첫·마지막 연결의 `ts`와 `_write_ts`. 일정과의 차이를 본다.
2. 바로 뒤 Slowhttptest(10:14\~10:35)와의 구분. 일정상 간격이 4분이고 대상이 같다.
   - 정답 에피소드는 시나리오가 다르면 둘로 나누는 것이 규칙이다.
   - 탐지 사건은 연속 후보 창 병합으로 하나가 될 수 있다. 그러면 일대일 대응에서 하나만 인정된다. 이 경우는 공격 포함 Recall과의 차이로 드러난다.
3. 선택 조건 초안: 캡처, 상대 `172.16.0.1`, 대상 `.50`, 포트 80, 시간 범위. 이 조건이 같은 시간대의 다른 활동과 공격을 분리하는지 대표 구간으로 확인한다.

## 2. 정상 비교: 월요일 `192.168.10.50`의 responder 활동

| 항목 | 내용 | 근거 수준 |
| --- | --- | --- |
| 출처 | 월요일은 데이터셋 설명상 정상 트래픽만 있는 날이다. 이 프로젝트의 학습·보류 구간이다 | 데이터셋 설명. 개별 연결의 정상 여부는 확인하지 않았다 |
| 대상·역할 | `192.168.10.50`, `responder` | — |
| 기존 측정 | 월요일 `.50`의 responder 5분 창은 98개다. `172.16.0.1`의 월요일 연결은 1건이다 | 이전 측정. 조건: `ts` 기준, 문자열 접두사 판정, 기존 Parquet. 새 계약의 값이 아니다 |

**이 비교가 보여 주는 것:**
- `.50`이 평소 어떤 규모와 형태로 연결을 받는지의 기준이다. 모델은 이 분포를 학습한다.
- 월요일에는 `172.16.0.1` 활동이 거의 없다. 그래서 수\~금의 공격 대부분은 "평소 없던 상대가 많은 연결을 보낸다"는 형태로 보일 수 있다.
  - 기존 측정에서 일정 기준 14개 후보 중 12개가 `172.16.0.1 → 서버` 방향이었다.
  - 모델이 공격 행동이 아니라 NAT 주소 활동 자체에 반응할 위험이 있다. 이것이 설계 6.1절의 특정 NAT 주소 편향 진단을 필수로 둔 이유다.
- 주 모델은 IP 값을 입력으로 쓰지 않는다. 그래도 연결 수·상대 수·지속시간 같은 특징을 통해 이 편향이 간접적으로 들어올 수 있다.

**보이지 않는 것과 한계:**
- "정상"은 데이터셋 설명 수준의 근거다. 개별 연결을 검증하지 않았다. 설계 5.1절에 따라 정상 비교 사례에는 근거 수준을 구분해 표기한다.
- 월요일 하루, 약 8시간이다. 요일·시간대별 정상 변동은 담기지 않는다.
- 학습 구간의 행 수는 단계 2의 Spark 결과로 다시 대조한다(V3).

## 3. 두 사례에서 얻는 규칙

- 공격 창의 특징은 "공격 행동"과 "NAT 주소의 등장"이 섞인 신호다. 탐지 결과를 해석할 때 둘을 구분해야 한다.
- conn의 기록 지연 때문에 탐지 시각과 공격 시각은 다를 수 있다. 정답 대응은 시간 중첩이 아니라 연결 참조로 한다(설계 5.3절).
- 근거 수준은 사례마다 표기한다: 일정, 데이터셋 설명, 이전 측정(조건 명시), 이번 단계의 직접 확인.

## 사용자 요구 (2026-11-05)

- Spring Boot로 만드는 **관리자 페이지** 형태의 대시보드다.
- 구현은 작은 데모다. 하지만 **고객에게 서비스될 실제 웹서비스의 일부**를 구현한 것처럼 만든다. 일반적인 웹서비스가 고려할 것은 모두 고려한다.
- 보안 회사에 지원하므로 보안을 신경 써서 만든다.
  - 인증
  - 인가
  - 방화벽
  - WAF

## Claude가 더한 고려사항

데모에서 무엇을 실제로 구현하고 무엇을 문서로만 남길지는 프롬프트를 만들 때 정한다.

### 인증
- 비밀번호 저장: 강한 해시(Argon2id 또는 bcrypt).
- 관리자 2단계 인증(TOTP).
- 무차별 대입 방어: 로그인 시도 제한, 계정 잠금.
- 세션
  - 로그인할 때 세션 ID를 새로 발급한다(세션 고정 방지).
  - 유휴 만료와 절대 만료를 둔다.
- 실서비스라면 SSO(OIDC)를 쓴다. 데모에서는 자체 로그인을 쓰거나 Keycloak 연동 중에서 고른다.

### 인가
- 역할 기반 권한(RBAC). 예: 조회자, 분석가, 관리자. 서버에서 모든 요청을 검사한다. 화면 버튼을 숨기는 것만으로는 막지 못한다.
- **객체 수준 권한:** 요청한 사건·자산을 이 사용자가 볼 수 있는지 매번 확인한다(IDOR 방지).
- **고객사(테넌트) 분리:** 고객 서비스라면 다른 고객사의 데이터가 섞이지 않아야 한다.
- **위험한 작업의 추가 확인:**
  - 대상: 모델 롤백, 알림 정책 변경.
  - 확인 방법: 재인증이나 2인 승인.
- DB 계정은 최소 권한으로 둔다. 대시보드는 읽기 전용 뷰만 읽는다.

### 웹 취약점 (OWASP Top 10 기준)
- **SQL 인젝션:** 항상 파라미터 바인딩을 쓴다. MyBatis에서는 `#{}`을 쓰고 `${}`을 쓰지 않는다.
- **XSS:** 출력할 때 인코딩하고 CSP를 건다.
  - LLM 보고서와 로그 값은 **신뢰하지 않는 입력**으로 취급한다. 프롬프트 인젝션된 문장이 화면에 그대로 실행되면 안 된다.
- **CSRF:** 토큰을 쓰고 쿠키에 `SameSite`를 건다.
- **오류 응답:** 스택 트레이스와 내부 정보를 노출하지 않는다.
- **입력 검증:** 서버에서 검증한다.
- **Spring Actuator:** 외부에 노출하지 않는다.

### 전송·헤더·쿠키
- TLS(리버스 프록시에서 종료), HTTP→HTTPS 전환, HSTS.
- 보안 헤더: CSP, `frame-ancestors`(클릭재킹 방지), `X-Content-Type-Options`, `Referrer-Policy`.
- 쿠키: `Secure`, `HttpOnly`, `SameSite`.

### 네트워크·방화벽·WAF
- 리버스 프록시(Nginx) 앞에 WAF를 둔다. 예: ModSecurity + OWASP CRS. Docker로 시연할 수 있다.
- 관리자 페이지는 허용된 주소나 VPN에서만 접근한다.
- 컨테이너 네트워크를 분리한다. DB와 내부 API는 외부에 포트를 열지 않는다.
- 요청 속도 제한.

### 감사·로그
- 관리자 행위 감사 로그: 누가, 언제, 무엇을, 어디서 했는지 남긴다.
- 감사 로그는 수정·삭제할 수 없게 저장한다.
- 로그에 비밀번호, 토큰, 개인정보를 남기지 않는다. 필요하면 마스킹한다.

### 데이터·개인정보
- IP 주소는 개인정보가 될 수 있다. 다음을 정한다.
  - 화면의 마스킹 정책
  - 권한별 원문 열람
  - 보존 기간
- 비밀값(DB 비밀번호, 키)은 코드와 Git에 넣지 않는다. 환경 변수나 비밀 저장소를 쓴다.

### 공급망·검증
- 의존성 취약점 검사(OWASP Dependency-Check 등)와 SBOM.
- 정적 분석과 컨테이너 이미지 스캔(Trivy 등).
- 보안 테스트
  - 인가 우회 시험: 다른 역할이나 다른 고객사로 접근해 본다.
  - OWASP ZAP 스캔 결과를 포트폴리오에 넣는다.

### 운영
- 상태 확인(health check)과 모니터링.
- 백업.
- 설정을 환경별로 분리한다(개발·운영).

## 대시보드 기능 후보 (zeek_AD와 연결)

- **사건 조사 큐:** 점수, 순위, 상태 필터.
- **사건 상세**
  - 근거 연결
  - IF와 Transformer 점수
  - RAG가 찾은 ATT&CK 근거
  - LLM 보고서
- **판단 모델과 Slack 전송 이력:** 그림자 비교 결과를 포함한다. 판단 모델은 DD-011에 따라 `gemini-decision-1`이다.
- **분석가 승인:** LangGraph의 승인 대기(interrupt)를 화면에서 승인·거절해 재개한다.
- **모델 버전과 롤백 상태:** 롤백 실행은 위험한 작업이므로 추가 확인을 거친다.

## zeek_AD 쪽에서 정할 것 (단계 4)

- 대시보드가 읽는 방식을 정한다. 둘 중 하나다.
  - PostgreSQL 읽기 전용 뷰와 전용 계정
  - Python 내부 API와 서비스 간 인증
- 계약에 넣을 것: 스키마, 필드 의미, 버전.

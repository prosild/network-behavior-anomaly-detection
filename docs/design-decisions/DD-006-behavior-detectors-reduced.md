# DD-006. 행동별 탐지기와 자명한 기준선 추가(축소안)

- 결정일: 2026-11-06
- 요청·결정: 사용자. 외부 검토 권고를 Claude가 0단계로 확인했고, 사용자가 축소안을 승인했다.
- 관련: [설계 질문 기록](../design-discussion-log.md) Q21\~Q26, [DD-002](DD-002-transformer-langgraph-rag.md), [DD-005](DD-005-deadline-scope.md)

## 배경

- 호스트 요약 18개 특징으로는 "누구와 연결했나"가 사라진다(Q21, Q22).
- 이 프로젝트가 겨냥하는 것은 룰을 피하는 행동이다. 측면 이동, 드문 목적지, beaconing이 그 예다(Q23).
- NAT 주소 지식만으로 Recall@10 12/16이 나온다. 이 값은 모든 모델보다 높다(단계 3a). 이 함정을 드러내는 기준선이 필요하다.
- 사건 분모는 16건이다. 1건 차이가 6.25%p이므로 신뢰구간이 필요하다.

## 결과 노출 공개

이 결정은 단계 3a·3b의 화\~금 결과를 본 뒤에 내렸다. 0단계 확인 때 화·목요일 공격 로그(ssh, ftp, http)도 직접 봤다.
- 그래서 여기서 추가하는 탐지기와 특징의 결과는 **독립 평가가 아니다**. 결과 문서에 "결과 노출 이후 설계 변경"으로 적는다.
- 각 탐지기의 파라미터는 구현 직후, 화\~금 평가 전에 설정 파일로 고정한다.
- 이 저장소는 git 저장소가 아니다. 그래서 커밋 해시 대신 평가 결과에 설정·코드 파일의 SHA-256을 남긴다.

## 범위 (11-07\~10)

| 순서 | 작업 | 내용 |
| --- | --- | --- |
| 1 | 자명한 기준선과 신뢰구간 | 기준선 A는 단계 3a의 NAT 진단(`nat_presence`, `nat_count`)을 그대로 쓴다. 기준선 B는 창에서 월요일 train에 없던 외부 IP 상대의 수다. 모든 결과에 사건 단위 bootstrap 95% 구간(16건 합계, 1,000회, seed 42)을 붙인다 |
| 2 | 행동별 탐지기 3개 | first-seen(관계 처음 등장), 내부 fan-out·스캔, beaconing(직접 구현). first-seen은 172.16.0.0/24를 뺀 진단 점수도 낸다 |
| 3 | Zeek 로그 특징 | 재처리 없이 만들 수 있는 ssh, http, dns 특징. 기존 18개 특징에 더해 IF·꼬리 희귀도를 다시 돌리고, 확장 전후를 따로 보고한다 |
| 4 | 커버리지 행렬과 위험 누적 | 행은 사건 16건, 열은 탐지기다. 탐지기별 고유 기여와 합집합 Recall을 보고한다. 자산 단위 위험 누적은 간단한 형태로 한다 |

## 바꾸지 않는 것

- 평가 규약: (캡처, 자산, 역할, 5분 창) 점수, 사건 생성, Recall@N, 고정 해시 동점, 캡처 양끝 제외.
- 새 탐지기도 같은 (자산, 역할, 창) 점수로 출력한다. 시간 척도가 다른 탐지기(beaconing)는 점수를 해당 구간의 창에 배정한다.
- 전처리 적합(중앙값, 표준화, seen-set 초기값, 분포 기준)은 월요일 train 구간에서만 한다.
- 임계값은 기본적으로 월요일 holdout p95다. 탐지기별 예외는 평가 전에 설정 파일에 적는다.
- 기본 모델(IF)과 단계 4 이후 일정(DD-005)은 그대로다.

## 미루는 것

다음은 후속 계획으로 포트폴리오에 적는다.
- Suricata 룰 기준선
- 그래프 오토인코더(Q24, Q25)
- 합성 주입 실험
- Zeek 재처리가 필요한 특징: FTP 로그인 응답, `community_id`, JA3/JA4
- 느린 유출 CUSUM, 인증 실패 탐지기

## 수정(2026-11-06, 사용자 결정)

- 이 프로젝트의 목적은 전통적인 ML 모델과 딥러닝 모델로 APT 같은 행동 이상에 대응하는 것이다. 사람이 정의한 행동 탐지기는 목적이 아니다.
- **중단:** 남은 행동 탐지기(fan-out, beaconing)와 위험 누적.
  - 이미 만든 기준선 A·B, first-seen, 신뢰구간은 비교용 참고 행으로만 남긴다. 더 확장하지 않는다.
- **새 우선순위:**
  1. Zeek 프로토콜 로그 특징(dns, http, ssl, ssh, smb·dce_rpc·kerberos)을 `uid`로 conn과 조인해 (자산, 역할, 창) 특징에 추가한다.
  2. 확장 특징으로 IF·꼬리 희귀도·Transformer를 다시 학습·평가하고, 확장 전후를 따로 보고한다.
     사용자의 스냅샷 GAT 그래프 오토인코더(Q25)를 같은 단계에 복원한다. 축소안에서 미룬 것은 사용자에게 분명히 알리지 않은 채 빠진 것이다. 노드 속성은 확장 특징을 쓰고, 구조 디코더는 방향을 표현하도록 비대칭(z_uᵀWz_v)으로 둔다.
  3. 합성 APT 패턴 주입으로 ML·DL 모델을 시험한다.
- 합집합 사건 생성(DD-002 3절)은 ML 모델들 사이의 결합 문제로 다룬다. 2번이 끝난 뒤에 정한다.

## 진행 방식

- 검증은 꼭 필요한 것만 둔다. 기준은 "하지 않으면 결과가 틀릴 수 있는가"다. 필요한 검증은 Claude가 직접 실행하고 결과를 보고한다. 사용자에게 같은 실행을 반복시키지 않는다.
- 개념 설명은 짧게 하고, 코드는 단계 단위로 묶어 낸다.

## 외부 서비스 키

Jev·LLM·Slack 키는 해당 단계에서 사용자가 발급한다. 그전에는 다음처럼 키 없이도 돌아가게 만든다.
- 외부 호출은 인터페이스 뒤에 둔다.
- 키가 없으면 대체 동작을 쓴다.
  - Jev: 정책 규칙으로 대신 판단한다.
  - Slack: 실제로 보내지 않고 파일에 기록한다(dry-run).
  - LLM: 템플릿 보고서를 쓴다.

## Java 관리자 대시보드

- Spring Boot 관리자 대시보드는 **별도 Java 프로젝트**로 만든다. 다른 AI 에이전트가 구현한다.
  - 설계 1절은 Spring API를 "후속 검토"로 두었다. 이 결정으로 별도 프로젝트로 바꾼다.
- 이 프로젝트가 할 일은 두 가지다.
  - 단계 4에서 대시보드가 읽을 **데이터 계약**(DB 뷰 또는 API, 권한)을 고정한다.
  - 구현을 마치면 [요구사항 문서](../java-admin-dashboard-requirements.md)를 기준으로 Java 프로젝트 에이전트용 프롬프트를 만든다.

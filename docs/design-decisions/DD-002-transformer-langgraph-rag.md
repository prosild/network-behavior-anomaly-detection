# DD-002. Transformer 이상탐지·LangGraph·RAG를 필수 범위에 포함

- 결정일: 2026-11-03
- 요청·결정: 사용자. 구현 형태와 안전 조건은 Claude가 제안했고, 사용자가 바꿀 수 있다.
- 이유: 채용 요건에서 시계열 딥러닝, LangGraph, RAG(vector DB) 경험이 중요하다. 포트폴리오에서 직접 구현하고 평가한 결과를 보여 준다.
- 관련: [DD-001](DD-001-slack-delivery-jev-gate.md)

## 바뀌는 설계 문장

| 최종 설계 위치 | 이전 | 변경 |
| --- | --- | --- |
| 1절 | RAG·Jev·LangGraph의 운영 경로 편입은 효과 확인 뒤 결정 | RAG·LangGraph는 첫 제출본의 필수 구현이다. Jev는 DD-001을 따른다 |
| 6.2절 | 모델 확장은 다음 버전의 별도 실험 | Transformer 비교 모델을 단계 3의 필수 구현으로 둔다. 1분 창 등 4개 선택 실험의 예산과는 별개다 |

탐지 입력, 시간 계약, 사건 생성, Recall 평가 규약은 바꾸지 않는다. 사용자가 앞서 정한 내용 중 다음 두 가지는 이 결정으로 대체한다.
- "Transformer는 넣지 않는다."
- "LangGraph는 후속 확장으로 미룬다."

그래프 모델은 그대로 별도 프로젝트다.

## 1. Transformer 이상탐지 (단계 3)

- **학습 방식:** 자기지도 학습이다. 월요일 학습 구간의 정상 데이터만 쓰고, 라벨은 쓰지 않는다. 지도학습 분류기가 아니다.
- **기본 과제:** 자산·역할별로 직전 K개 창의 특징 시퀀스를 보고 다음 창의 특징을 예측한다. 예측 오차가 이상 점수다. 점수가 클수록 이상하다.
- **입력:** Gold의 같은 특징을 쓴다. IF와 같은 전처리를 학습 구간에서만 적합한다.
- **활동 없는 창:** 주 모델에는 활동 없는 창의 행이 없다. 시퀀스에는 빈 칸이 생기므로 "활동 없음" 표시를 넣어 시퀀스를 만든다. 이 규칙은 Transformer 입력에만 적용하고, 단계 3 구현 전에 확정한다.
- **평가:** IF와 같은 규약을 쓴다.
  - 월요일 보류 점수의 95번째 백분위수로 임계값을 정한다.
  - 같은 사건 생성 규칙과 Recall@N을 쓴다.
  - 긴 연결·NAT 편향 진단을 같이 한다.
- **K와 모델 크기:** 평가 전에 고정한다. 평가 결과를 보고 고르지 않는다.
- **알려진 위험:** 데이터가 작다.
  - 학습 구간은 자산·역할당 최대 76개 창이고, 전체 학습 행은 1,286개다.
  - IF보다 낫다는 결과를 기대하지 않는다. 지면 진 결과를 그대로 보고한다.
  - 포트폴리오에서 보여 줄 것은 "같은 평가 규약으로 공정하게 비교한 과정"이다.
- **기록:** MLflow에 실행을 기록하고 PyTorch 모델을 등록한다. 배포 묶음 규칙(설계 8절)을 똑같이 따른다.

## 2. RAG와 vector DB (단계 5)

- **문서:** 버전을 고정한 공개 자료만 쓴다. MITRE ATT&CK, 필요하면 Zeek 공식 문서. 로그 원문이나 사건 데이터는 색인하지 않는다.
- **vector DB:** PostgreSQL의 `pgvector`가 기본이다. 이미 사건 저장에 쓰는 PostgreSQL이라 서비스를 늘리지 않는다. 다른 vector DB로 바꾸려면 이유를 기록한다.
- **임베딩:** 로컬 모델로 시작한다. 모델 ID와 버전을 고정한다.
- **비교:** 같은 질의 세트로 키워드 검색(BM25), 벡터 검색, 혼합 검색을 비교한다.
  - 검색 정확도(recall@k)와 보고서 개선을 따로 측정한다(설계 9.2절).
  - 질의 세트와 기대 문서는 결과를 보기 전에 정한다.
- **해석:** ATT&CK 매핑은 행동 설명의 가설이다. 공격 정답이 아니다.
- **비신뢰 입력:** 검색된 문서도 비신뢰 입력으로 취급한다. 예산을 정한 인젝션 시험을 넣는다.

## 3. LangGraph (단계 5)

사용자가 의도한 흐름을 구현한다(2026-11-03 보완). 이 흐름에는 병렬 수집·종합, 반복, 대기·재개가 들어간다. 그래서 설계 9.2절의 LangGraph 도입 조건에 맞는다.

```
                ┌→ IF 근거 수집 ─────────┐
사건 → 시작 ────┤                        ├→ 종합(코드) → LLM 보고서 → Jev 판단 ─┬─ 보냄 → Slack
                ├→ Transformer 근거 수집 ┤                                     ├─ 보류 → 기록(조사 큐 유지)
                └→ RAG 조회 ─────────────┘        ↑                            ├─ 추가 근거 필요 → 재수집(반복 상한)
                                                  └────────────────────────────┤
                                                                               └─ 분석가 확인 필요 → 대기(interrupt) → 재개
```

**모델 점수는 LangGraph에서 계산하지 않는다.**
- IF와 Transformer는 창이 확정될 때 추론 worker가 점수를 계산해 저장한다. 모델은 탐지를 해야 하므로, 조사 흐름이 시작되기 전에 이미 돌아가 있어야 한다.
- LangGraph의 수집 노드는 저장된 두 모델의 점수·순위·임계값 대비 위치·관련 연결 근거를 **조회**한다.
- 세 노드를 병렬로 실행하고, 모두 끝나면 종합 노드로 모은다(fan-out/fan-in).

**사건 생성 기준(기본값):**
- IF가 사건을 만들고 조사 큐 순서를 정한다.
- Transformer 점수는 같은 창의 두 번째 의견으로 붙는다.
- 단계 3 비교에서 Transformer가 IF가 놓친 confirmed 에피소드를 찾으면, 두 모델 후보의 합집합으로 사건을 만드는 방식을 검토한다. 그때 결합 순위 규칙은 평가 전에 정하고, 같은 Recall 규약으로 따로 평가한다.

**종합과 판단의 입력:**
- 종합 노드는 코드다. 두 점수를 같은 척도(각 모델의 월요일 보류 분포 대비 백분위)로 맞춘다. 일치·불일치를 표시한다. LLM이 숫자를 계산하게 하지 않는다.
- LLM은 종합 결과로 사람이 읽을 보고서를 쓴다.
- Jev는 종합된 구조화 근거를 주 입력으로 판단한다. LLM 보고서 문장을 판단 근거로 삼으면, LLM의 근거 없는 주장이 전송 판단으로 옮겨 갈 수 있기 때문이다. 보고서를 보조 입력으로 줄지는 그림자 비교에서 따로 확인한다.

- **먼저 일반 함수로 만든다.** 같은 흐름의 직선 버전을 만들고, LangGraph 버전과 결과·지연·코드 복잡도를 비교한다.
- **반복 상한:** 추가 근거 조회를 무한히 반복하지 않는다. 상한에 닿으면 정책 규칙을 따른다.
- **상태 저장:** checkpointer로 대기 중인 사건의 상태를 저장한다. 프로세스를 재시작해도 이어서 진행되는지 확인한다.
- **DD-001 유지:** 필수 전송 조건, 실패 시 정책 규칙, 조사 큐 비억제, 미전송 공개를 그대로 지킨다.
- **추적:** 각 노드의 입력·출력을 MLflow Tracing으로 기록한다.

## 학습 계획

사용자는 vector DB·RAG·LangGraph·LangChain을 대략적으로만 안다. 그래서 단계 5에서 시스템에 붙이기 전에 작은 학습 예제로 원리를 먼저 익힌다. 사용자가 직접 실행하고 설명할 수 있어야 다음으로 넘어간다.

1. 임베딩과 유사도: 짧은 문장 몇 개를 벡터로 바꾸고, 코사인 유사도를 직접 계산한다.
2. vector DB: pgvector에 저장하고, 최근접 검색 SQL과 인덱스의 역할을 확인한다.
3. 키워드 검색과 벡터 검색: 같은 질의에서 BM25와 벡터 검색이 다른 문서를 찾는 사례를 본다.
4. RAG: 검색 결과를 프롬프트에 넣었을 때와 넣지 않았을 때의 답변을 비교한다.
5. LangGraph: 상태·노드·간선의 최소 그래프에서 시작해 하나씩 추가한다. 조건 분기, 병렬 fan-out/fan-in, 반복 상한, checkpointer, interrupt·재개 순서다.
6. LangChain: 필요한 구성요소만 쓴다. 예: 모델 호출 래퍼, pgvector 검색기. 직접 SDK 호출과 비교해 장단점을 설명한다.

# DD-009. ML·DL 결합: 하루 큐를 순위대로 번갈아 합친다

- 결정일: 2026-11-11
- 요청·결정: 사용자(설계 질문 기록 Q36). 대안 비교와 세부 규칙은 Claude가 제안했다.
- 관련: [DD-002](DD-002-transformer-langgraph-rag.md) 3절(합집합 사건 생성), [DD-006](DD-006-behavior-detectors-reduced.md) 수정 절, [DD-008](DD-008-synthetic-apt-injection.md)
- 설정: [configs/models/fusion.v1.json](../../configs/models/fusion.v1.json). 결합 평가 전에 고정했다.
- 결과 노출: 세 모델의 단독 결과(CIC·합성)를 본 뒤의 결정이다. 결과 문서에 그렇게 적는다.

## 결정

- 대상: TGN recon, 꼬리 희귀도 v2, Transformer v2. 셋은 잡는 패턴이 다르다(합성 평가: 창 모델은 정찰, Transformer는 측면 이동 후보, TGN은 beacon).
- 모델마다 기존 규약대로 하루 큐를 만든다(보류 p95, 사건 묶기, 점수·고정 해시 순서).
- 1회차에 TGN 1위 → 꼬리 1위 → Transformer 1위, 2회차에 각 2위, ... 순서로 뽑는다.
- 이미 뽑힌 사건과 같은 캡처·자산·역할에서 창을 하나라도 공유하면 건너뛴다. 그 모델의 차례는 쓴 것으로 친다.
- 합친 큐에는 점수가 없다. 순서가 순위다.
- 합성 평가의 주 큐는 모델별 큐에서 CIC 사건을 뺀 뒤 합친다.

## 점수를 섞지 않는 이유 (검토한 대안)

세 점수는 단위와 꼬리 모양이 다르다. 월요일 정상 구간 기준으로 맞춰 세 모델 창을 섞고 하루 상위 창을 세었다.

| 방법 | 결과 |
| --- | --- |
| z-score(보류 평균·표준편차) | 상위 30창의 87~100%가 Transformer. 꼬리 희귀도는 z 3.2에서 멈춰 0창 |
| 로버스트 스케일링(보류 중앙값·IQR) | 상위 100창의 94~100%가 Transformer(IQR 0.39라 꼬리가 43.8까지 늘어남) |
| 보류 백분위(DD-002 종합 노드 방식) | 보류가 312창뿐이라 화~금 창 중 TGN 하루 24~55개, Transformer 2~63개가 모두 100 |
| min-max(그날 최댓값) | 큰 공격 하나가 나머지를 0 근처로 누른다(시험하지 않음) |
| 소프트맥스 | 순서를 바꾸지 않아 top-k가 정규화만 한 것과 같다 |

- 선형 변환은 중심과 폭만 맞추고 꼬리 모양을 맞추지 못한다. 상위 N은 꼬리에서 정해진다.
- 그날 안 순위로 바꾸는 것(순위 정규화)이 꼬리 모양까지 같게 만든다. 그 순위로 섞는 것이 번갈아 합치기다.
- 약점: 그날 쓸 만한 사건이 없는 모델도 같은 몫을 받는다. 상위 N 예산이 모델 수로 나뉜다.

## 바꾸지 않는 것

각 모델의 학습·점수·임계값, 평가 규약(사건, Recall@N, 일대일 대응). DD-002 9절의 LLM 역할(보고서 작성, 탐지기 아님).

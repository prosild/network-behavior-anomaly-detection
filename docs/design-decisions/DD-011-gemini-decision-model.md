# DD-011. Slack 전송 판단 모델을 Jev에서 Gemini Decision 1로 바꾼다

- 결정일: 2026-11-14
- 요청·결정: 사용자(설계 질문 기록 Q40, "동의하고"). Claude가 공식 문서를 확인하고 추천했다.
- 관련: [DD-001](DD-001-slack-delivery-jev-gate.md), [DD-005](DD-005-deadline-scope.md), 설계 9절

## 결정

DD-001의 판단 모델(Slack 전송 여부를 고르는 모델)을 TypeSafe AI Jev에서 Google `gemini-decision-1`(Gemini Developer API `v1beta`, `/decisions`)로 바꾼다. Jev는 키가 생기면 같은 그림자 비교에 추가할 수 있는 후보로 남긴다.

DD-001의 나머지는 그대로다.
- 판단 대상은 Slack 알림 여부뿐이다. 조사 큐는 억제하지 않는다.
- 필수 전송 조건은 판단 모델이 막지 못한다. 실패·시간 초과·형식 오류면 정책 규칙을 쓴다.
- 정책 규칙·일반 LLM·판단 모델을 같은 사건에서 비교(그림자)한 뒤 전환을 정한다.
- 입력은 설계 9.1절 허용 목록 필드만 보낸다(사용자명·호스트명·자유 문자열 금지).
- confidence를 정확도로 해석하지 않는다.

## 이유

- 같은 종류의 모델이다. 글을 생성하지 않고, 정해 둔 질문에 형식이 정해진 답(`noul` 예/아니오 확률, `choice` 선택지별 확률, `score` 순서 등급)과 confidence를 돌려준다. DD-001에서 Jev에 맡긴 일(보냄·보류·추가 근거 요청·분석가 확인 중 하나를 고름)을 그대로 할 수 있다.
- 지금 쓸 수 있다. Jev 키는 없어 DD-005에 따라 정책 규칙으로 대신할 계획이었다. Gemini 키는 이미 `deploy/.env`에 있고, SDK도 RAG 임베딩에 쓰는 `google-genai`(3.2 이상)와 같다.

## 확인한 사실과 주의(공식 문서, 2026-11-14 조회)

- 2026-11-11 공개된 베타다. 모델 ID·SDK 버전을 고정하고, 응답에서 모델 버전을 기록한다. 응답 형식은 연동할 때 다시 확인한다.
- confidence는 "가장 높은 답이 맞을 추정 확률"이고 최고 확률과 같다. 문서는 보정됐다고 하지만 수치를 내지 않고, 임계값은 자기 데이터의 라벨로 정하라고 한다.
- 선택지 키는 UTF-8 바이트 순으로 정렬되고, 완전 동점이면 앞선 키가 이긴다. 선택지 이름에 우선순위를 담지 않는다.
- 무료 등급에서는 입력이 제품 개선에 쓰일 수 있다. 이 프로젝트는 공개 CIC 자료의 허용 목록 필드만 보내므로 연습에는 문제가 없다. 운영이라면 유료 등급을 쓴다.

## 구현 위치

판단 호출은 공급자별 작은 함수 하나로 둔다(입력: 허용 목록 근거, 출력: 선택·선택지별 확률·confidence·모델 버전). 단계 5b에서 만든다.

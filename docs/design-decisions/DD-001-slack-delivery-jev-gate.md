# DD-001. Slack 보고 전달과 Jev 전송 판단

- 결정일: 2026-11-03
- 요청·결정: 사용자. 구조와 안전 조건은 Claude가 제안했다.
- 관련 설계: [최종 설계](../../FINAL_PROJECT_DESIGN.md) 4.1절 `delivered_at`, 9절, 10절
- 성격: 전달 경로를 추가한다. 탐지·사건 생성·Recall 평가 규약은 바꾸지 않는다. 모델 설정 변경이 아니므로 비교 횟수 기록은 해당하지 않는다.

## 결정

1. 최종 보고는 Slack으로 전달한다.
2. 사건을 Slack에 보낼지는 Jev가 판단하는 구조를 목표로 한다.

## 목적

보안관제팀의 알림 피로도를 줄인다. 모든 사건을 알림으로 보내면 중요한 사건이 묻힌다. 그래서 의사결정 모델인 Jev가 알림이 필요한 사건을 고른다. 판단과 이유는 모두 기록한다.

## 바꾸지 않는 원칙

- **모든 사건은 조사 큐(PostgreSQL)에 남는다.** Slack에 보내지 않은 사건도 삭제하거나 숨기지 않는다. 설계 9.2절의 "조사 큐를 자동 억제하지 않는다"를 지킨다. Jev가 정하는 것은 Slack 알림 여부뿐이다.
- **Recall@N은 조사 큐에서 계산한다.** Slack 전송 판단의 성능은 따로 측정한다.
- **최종 판단은 사람이 한다.** Jev와 LLM은 알림 여부와 보고서만 다룬다. 차단이나 공격 확정은 하지 않는다.

## 단계적 도입

| 단계 | Slack 전송을 정하는 것 | Jev의 역할 |
| --- | --- | --- |
| A. 그림자 | 명시적 정책 규칙 | 같은 사건에 판단만 내리고 기록한다. 전송에는 영향을 주지 않는다 |
| B. 전환 | Jev | A의 비교 결과로 전환을 결정한다. 결과가 부족하면 A를 유지하고 이유를 기록한다 |

A의 비교 대상은 같은 사건에 대한 세 가지 판단이다: 정책 규칙, 일반 LLM, Jev. 측정 항목은 다음과 같다.
- 사람 판단과의 일치.
- 공격 관련인데 보내지 않은 사건 수.
- 불필요하게 보낸 사건 수.
- 관측 시간당 Slack 알림 수. 피로도 지표다. 불완전한 캡처를 24시간 운용 실적으로 환산하지 않는다.
- 판단 비용과 지연.

모든 판단(정책 규칙·Jev·대체 사용 여부)과 이유는 사건별로 저장한다. Jev 호출은 MLflow Tracing으로 기록한다.

## Jev 판단의 안전 조건

- **필수 전송 조건은 Jev가 막지 못한다.** 정책 규칙에 반드시 보내는 조건을 둔다. 구체 조건은 단계 5에서 점수를 보기 전에 정한다.
- **실패 시 정책 규칙을 따른다.** Jev가 실패하거나 시간 초과·형식 오류를 내면 정책 규칙의 결정을 쓴다.
- **보내지 않은 사건도 보이게 한다.** Slack 일일 요약에 미전송 사건의 개수와 사건 ID를 공개한다.
- **confidence는 정확도가 아니다.** Jev의 confidence를 실제 정확도로 해석하지 않는다.
- **입력은 허용 목록으로 제한한다.** Jev의 입력은 설계 9.1절의 LLM 입력 경계를 따른다.

## LangGraph와의 관계

전송 판단은 일반 함수로 먼저 만든다. 순서는 필수 전송 조건 → Jev 판단 → 실패 시 정책 규칙이다.

그다음 [DD-002](DD-002-transformer-langgraph-rag.md)에 따라 같은 판단을 LangGraph 흐름으로 구현한다. 이 흐름에는 두 가지가 들어간다.
- Jev가 추가 확인을 요청하면 근거를 더 조회한 뒤 다시 판단하는 분기. 반복 상한을 둔다.
- 분석가 검토를 기다렸다가 재개하는 흐름.

두 버전은 결과와 지연을 비교한다.

## Slack 전송 규약

- **멱등성:** `(event_id, report_version)`을 유일 키로 전송 기록을 남긴다. 재시도해도 같은 메시지가 중복되지 않게 한다. `delivered_at`과 Slack 메시지 식별자를 저장한다.
- **내용:** 사건 ID, 요약, 근거 ID, 조회 API 링크만 보낸다. 원문 로그와 자유 형식 문자열은 넣지 않는다. Slack은 외부 서비스이므로 보내는 필드를 허용 목록으로 관리한다.
- **비밀값:** 토큰·Webhook URL은 Git과 MLflow에 넣지 않는다.
- **API 형식:** Jev와 Slack의 API 형식·모델 ID는 연동 시 공식 문서로 확인하고 고정한다.

## A단계 비교 결과(2026-11-17)

판단 모델은 DD-011에 따라 Jev 대신 `gemini-decision-1`이다. 측정 항목에서 사람 판단 일치는 뺐다(DD-014). 자세한 수치는 [단계 5 진행 기록](../stage-5-progress.md) 아홉째·열째 작업에 있다.

- 평가 세트(목·금, 동결 후) 30건 중 공격 관련은 26건이다.
- 정책 규칙: 보냄 29, 놓친 공격 0.
- 일반 LLM·판단 모델: 각각 보냄 16. 공격 관련 11건을 지금 보내지 않았다(대부분 검토 요청).
- 필수 전송 조건(큐 5위 이내 또는 2개 이상 모델)이 표본 30건 중 29건에 걸렸다. 그래서 판단 모델을 붙여도 알림이 줄지 않았다.
- 결론: **B 전환을 보류하고 A(정책 규칙)를 유지한다.** 판단 모델은 그림자로 계속 기록한다.

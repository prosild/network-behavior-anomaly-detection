# DD-017. 실습망 시험에 정상 배경 트래픽(월요일 재생 + 합성)을 섞고, 공격은 그 중간에 넣는다

- 결정일: 2026-11-19
- 요청·결정: 사용자(A·B를 섞고 공격을 중간에 넣자는 제안). 대역·시간표·표시 규칙은 Claude가 정했다.
- 관련: [DD-008](DD-008-synthetic-apt-injection.md)(합성 주입 원칙), [DD-015](DD-015-vmware-lab-deployment.md), [DD-016](DD-016-lab-capture-coverage-and-report-refresh.md), [설계 질문 기록](../design-discussion-log.md) Q58

## 배경
- 실습망에는 평소 정상 트래픽이 없다. Kali 공격만 보내면 "공격 창에서 사건이 생기는가"만 보이고, 정상 트래픽을 잘못 잡는지(오탐)와 정상 속에서 공격이 묻히는지는 보이지 않는다.
- 11-17 시험 PCAP(합성 정상 클라이언트 + 스캔)에서는 스캔 대상과 통신한 정상 클라이언트도 TGN이 꼽았다(그래프 이웃 전파). 그 시험은 합성 정상(B)만 썼고, 파일로 넣었다(실제 수집 경로가 아님).
- 모델이 아는 정상은 CIC 월요일이다. 정상의 모양에 따라 결과의 뜻이 다르다(Q58).

## 결정
1. **배경은 두 종류를 섞는다.**
   - A. 월요일 재생: CIC 월요일 **보류 구간**(18:24:27 UTC 이후, 학습에 쓰지 않은 부분)에서 35분을 잘라 IPv4만 남기고, 내부 주소(192.168.10.x)를 실습망 10.10.0.100번대로 하나씩 바꾼다. 외부 주소는 그대로 둔다(실습망은 격리돼 밖으로 나가지 않는다). MAC은 가짜(로컬 관리 주소)로 바꾼다. 모델 기준의 정상이다.
   - B. 합성 정상: 11-17 시험과 같은 생성기([tests/pcap_fixture.py](../../tests/pcap_fixture.py) `lab_traffic`). 클라이언트 10.10.0.11·.12가 10초마다 DNS(가짜 서버 10.10.0.53)와 HTTP를 보낸다. HTTP 서버는 **실제 공격 대상인 배포 VM(10.10.0.10)**으로 둔다. 11-17의 구조(정상 클라이언트가 스캔 대상과 통신)를 실제 수집 경로에서 다시 보기 위해서다.
2. **보내는 방법**: 배포 VM에서 일회용 컨테이너(host 네트워크, NET_RAW)의 tcpreplay가 실습용 카드로 원래 시간 간격(1배속) 그대로 보낸다. 수집기(tcpdump)는 그 카드에서 나가는 패킷도 캡처하므로, 이후 경로(수집 → Zeek → 다시 계산 → 채점 → 에이전트)는 실제와 같다. Kali는 건드리지 않는다.
   - 큰 프레임: 잘라낸 A의 약 10%(42,058개)가 1,514바이트보다 크다(최대 8,754, CIC 캡처의 합쳐진 TCP 조각). 빼면 연결이 끊기고, 쪼개면 모델이 월요일에 본 패킷 수가 달라진다. 그래서 재생하는 동안만 실습용 카드 MTU를 9000으로 올려 그대로 보내고 끝나면 되돌린다([scripts/lab_replay.sh](../../scripts/lab_replay.sh), 카드 e1000 최대 16,110). 수집기는 나가는 프레임을 카드에 넘기기 전에 캡처한다.
   - 만드는 코드: [scripts/build_lab_background.py](../../scripts/build_lab_background.py), [zeek_ad/lab_background.py](../../zeek_ad/lab_background.py)(주소 바꾸기, 체크섬 증분 갱신), 재생 이미지 [deploy/replay.Dockerfile](../../deploy/replay.Dockerfile). 결과물은 `outputs/lab_background/v1/`(manifest.json).
   - 충실도 확인(2026-11-19): 배경 PCAP을 Zeek로 다시 돌려 원래 월요일 Zeek 출력(같은 35분)과 자산·역할별로 비교했다. 연결 33,622 → 33,842(구간 앞에서 시작한 연결이 잘려 새로 잡힌 몫), 자산별 패킷·바이트 차이 1% 안팎. IPv4가 아닌 프레임 5,344개(ARP·IPv6 등)는 뺐다.
3. **시간표(5분 칸 7개)**: 배경만 2칸 → 배경 + Kali 공격 3칸(`scripts/lab_scenario.sh`: ping, `nmap -sT`, `nmap -sV`) → 배경만 2칸. 앞뒤의 배경만 칸이 같은 실행 안의 대조군이다(같은 정상 자산이 공격 전후와 공격 중에 어떻게 다른지).
4. **표시와 해석**
   - 재생 manifest에 그룹별 IP(A·B·Kali·배포 VM)와 칸별 시각을 남긴다. 공격 시각은 Kali 스크립트 기록이다. 탐지 결과와 따로 둔 정답 시간표다.
   - 결과는 그룹별로 낸다. A·B는 "재생·합성 배경"으로 표시하고, 실제 관측 주장과 섞지 않는다(DD-008과 같은 원칙).
   - 예약 대역: B 10.10.0.11·.12·.53, A 10.10.0.100~.199. 실제 VM에 이 주소를 주지 않는다.

## 알아야 할 한계
- A는 2017년 사무실 트래픽을 다른 시각에 다시 보낸 것이다. 모델 특징에 시각(시간대) 값은 없어(2026-11-19 확인) 시각이 바뀐 영향은 작다고 보지만, 실습망 하루 그래프 안에서 TGN 기억·이웃은 원래와 다르다.
- 패킷은 배포 VM 자신이 보낸 것을 캡처한다. 실제 다른 호스트가 응답하지 않는다(재생 패킷에 양방향이 다 들어 있어 Zeek는 연결을 그대로 본다).
- B는 10초 간격으로 똑같이 반복해 비콘처럼 보일 수 있다. 11-17과 비교하려고 생성기를 바꾸지 않았다.
- 같은 날 먼저 한 공격만의 시험(기준 실행)이 TGN 기억에 남아 있다. 공격자가 다시 온 상황으로 본다.
- 배경 때문에 사건이 늘면 LLM 보고서(Gemini 호출)도 는다.

# DD-007. 사용자 설계의 TGN 이벤트 그래프 이상탐지

- 결정일: 2026-11-06

- 관련: [설계 질문 기록](../design-discussion-log.md) Q24·Q29~Q31, [DD-006](DD-006-behavior-detectors-reduced.md) 수정 절

## 설계 (사용자 아이디어)

- 노드는 IP이고, 엣지는 연결 하나하나다. 엣지는 시각이 붙은 이벤트다.
- 포트·연결 시간·바이트 같은 엣지 정보를 작은 모듈로 각각 벡터화해 concat한다.
- TGN으로 학습한다. 정상(월요일 train)만 학습하고, 잘 복원하지 못하면 이상으로 본다.
- 잠재 공간의 차이를 임계값과 비교한다.

## 세부

| 항목 | 내용 |
| --- | --- |
| 이벤트 | conn 한 행 = (출발 IP, 도착 IP, 시각, 엣지 정보). 시각은 기존 창 배정과 같은 `_write_ts`를 쓴다 |
| 엣지 정보 | conn: 받는 쪽 포트(서비스군), proto, service, conn_state, history, log1p 양(duration, 바이트, 패킷). `uid`로 붙인 로그: dns, http, ssl, ssh, ftp, smb, kerberos, dce_rpc. 해당 로그가 없으면 "없음" 값 |
| Zeek 재처리 | run.v2 = v1 + `tgn-extras.zeek`(community_id, FTP USER/PASS 기록). 출력은 `outputs/zeek/<요일>/run-02`. v1 결과는 그대로 둔다 |
| 모델 | TGN 메모리(IP마다 GRU 상태) + 시간 인코딩 그래프 attention 임베딩 + 방향을 구분하는 디코더 |
| 복원 목표 | 연결을 보기 직전의 z_출발, z_도착으로 그 연결의 엣지 정보를 복원한다 |
| 점수 | 복원 오차, 그리고 잠재 이동량 ‖z_후 − z_전‖. 주 점수와 결합 규칙은 평가 전에 설정으로 고정한다 |
| 평가 | 연결 점수를 (자산, 역할, 5분 창) 최댓값으로 모아 기존 규약(보류 p95, 사건, Recall@N)으로 평가한다 |
| 구현 | PyTorch Geometric(TGNMemory, LastNeighborLoader, TransformerConv). 엣지 모듈 concat, 임베딩, 디코더, 손실, 점수는 사용자가 실습 노트북에서 직접 구현한다 |

## 설계 과제와 대응

| 과제 | 대응 |
| --- | --- |
| 처음 보는 IP(화~금 노드의 38~45%)는 메모리가 0이다 | IP 속성 특징(내부/외부, 대역 해시, 포트 프로필)을 임베딩에 같이 넣는다 |
| 평가 중 메모리를 갱신하면 반복 공격이 익숙해진다 | 운영처럼 갱신하되, 점수는 갱신 전에 매긴다. 공격 구간의 점수 변화를 보고한다 |
| 연결의 60%가 DNS 서버 두 곳으로 간다 | 학습 손실에서 DNS 비중을 낮춘다. 평가에서는 모두 채점한다 |
| 172.16.0.1(NAT)에 공격이 몰려 있다 | 이 주소의 연결을 뺀 점수로 Recall을 한 번 더 낸다(해석용 진단) |

## 바꾸지 않는 것

평가 규약, 월요일 train/holdout 분할, 기존 모델 결과와 산출물.

## 3. 인용할 표와 문장

전체는 [실습망 공격 탐지 결과](lab-attack-detection.md)에 있다.

| 공격 | 실행 | 판정 | 첫 알림까지 |
| --- | --- | --- | --- |
| 빠른 스캔 | 2회 | 잡힘, 잡힘 | 7.0분, 15.2분 |
| 서비스 스캔 | 2회 | 잡힘, 잡힘 | 6.8분, 10.2분 |
| 느린 스캔 | 1회 | 잡힘 | 6.9분 |
| 측면 이동 | 1회 | 잡힘 | 3.6분 |
| 비커닝 | 2회 | 구분 안 됨, 후보만 | 없음 |
| 느린 유출 | 1회 | 후보만 | 없음 |
| DNS 터널 | 1회 | 후보만 | 없음 |
| SSH 무차별 대입 | 1회 | 놓침 | 없음 |

인용할 때 지킬 것.

- 탐지율이 아니다. 종류마다 1\~2회 실행한 프로브다. "8종 중 4종을 잡았다"까지는 쓸 수 있고 퍼센트로 쓰지 않는다.
- 판정의 뜻: 잡힘 = 공격 창에서 나온 알림이 있고 그 자산의 평소 창보다 점수가 높은 모델이 있다. 구분 안 됨 = 알림은 있었지만 평소보다 높은 모델이 없다. 후보만 = 모델 후보였지만 공격 창에서 나온 알림이 없다. 놓침 = 후보가 아니다.
- 걸린 시간은 첫 공격 연결부터 첫 알림 기록까지다. Slack은 dry-run이라 전송 시각이 아니라 기록 시각이다. 대부분은 5분 창이 닫히기를 기다리는 시간이고, 창이 닫힌 뒤로는 약 2분이다. 2회차 스캔(15.2분, 10.2분)은 배경 트래픽으로 사건이 몰려 채점이 밀린 경우다.
- 2회차 빠른 스캔과 서비스 스캔은 알림 하나에 함께 묶였다.

zeek_AD README에서 바뀐 표현(대시보드 README가 인용하고 있으면 맞춘다).

| 항목 | 전 | 후 |
| --- | --- | --- |
| 공격 종류 수 | 7종 | 8종(11회). 서비스 스캔을 따로 센다 |
| 느린 유출 | 약하게 | 후보만 |
| 비커닝 | 놓침 | 구분 안 됨(1회차), 후보만(2회차) |
| DNS 터널 | 놓침 | 후보만(서버 쪽 한 창만 후보, 알림 없음) |
| 스캔·측면 이동 | 잡음 | 잡힘 + 첫 알림까지 걸린 시간 |

CIC 평가 표(결합 v1 Recall@50 14/16, 합성 13/20 등)는 바뀌지 않았다.

# zeek_AD → 대시보드: 2026-11-21 변경 사항

대시보드 화면 표시에만 영향을 준다. **DB·뷰·API·DB 함수는 바뀌지 않았다.** 배포 VM에 반영할 것도 없다.
자세한 표는 [데이터 계약 v2](data-contract-v2.md)의 "모델 표시 이름"과 "수집 구간(캡처) 표시 이름" 절에 있다. 이 글은 요약이다.

## 1. 탐지 모델 표시 이름 확정(Q63)

T15에서 "zeek_AD 쪽 확정 필요"로 미룬 것을 확정했다. 사용자 결정이므로 "탐지 모델 이름은 바꾸지 않는다" 규칙(`labels.ts` 머리 주석, `docs/ui-terminology.md`)을 풀고 표시 이름 사전에 넣는다.

| 식별자 | 표시 이름 | 모델 종류 |
| --- | --- | --- |
| `tail_rarity_v2` | 기준선 이탈 | 통계 기준선 |
| `transformer_v2` | 행위 패턴 이탈 | Transformer |
| `tgn_recon` | 통신 관계 이상 | TGN(시간 그래프 신경망) |

- 툴팁 문장은 데이터 계약 표에 있다. 그대로 쓴다.
- 사건 목록 같은 표에는 표시 이름만, 상세 화면과 툴팁에는 모델 종류와 식별자를 함께 둔다(예: "Transformer · transformer_v2").
- 버전은 표시 이름에 넣지 않는다. 임계값 표시(운영 화면)의 키도 같은 사전으로 바꾼다.
- 적용할 값: `zeekad_picked_by`, `zeekad_also_flagged_by`, `zeekad_model`, `model_bundles.thresholds`의 키, `feedback_summary.zeekad_picked_by`(`'all'`은 지금처럼 "모든 모델 합계").
- 모델 구성(`zeekad-fusion/N`) 표시는 이번 결정에 들어 있지 않다. 지금 방식을 유지한다.

## 2. 수집 구간(캡처) 표시 이름(Q65)

캡처 ID가 그대로 보여 `syn1-*`을 Kali 트래픽으로 오해하는 일이 있었다. `syn1-*`은 Kali가 아니라 CIC 로그 사본에 코드로 끼워 넣은 합성 APT다. Kali 실행은 `lab-20261119`다.

| 캡처 ID 형식 | 표시 이름 |
| --- | --- |
| `cic17-<요일>` | CIC-IDS2017 <요일>요일 |
| `syn1-<요일>` | CIC <요일>요일 + 합성 APT |
| `lab-YYYYMMDD` | 실습망 YYYY-MM-DD |

- 실습망 캡처별 덧붙일 표시: `lab-20261119` "Kali 공격 + 정상 배경", `lab-20261118` "시험", `lab-20261201` "시험(가짜 패킷)".
- **`lab-20261201`은 시연 화면에서 숨긴다.** VM 전에 만든 가짜 패킷이다. DB에서는 지우지 않는다.
- 원래 캡처 ID는 툴팁에 둔다. 열람 허용 패턴(`cic17-*`, `syn1-*`, `lab-*`)은 ID 그대로 쓴다.

## 3. LLM 요청 모델이 gemini-3.8-flash로 바뀜(Q64, 화면 변경 필요 없음)

- 2026-11-21부터 새 보고서의 `llm_model_requested`가 `gemini-3.8-flash`다. 전에는 `gemini-3.7-flash`였다.
- 실제로 보고서를 쓴 모델(`llm_model_version`)은 전에도 `gemini-3.8-flash`였다.
- 예전 보고서는 "요청 3.7 / 응답 3.8"로, 새 보고서는 "3.8 / 3.8"로 보인다. 둘 다 정상이다.

## 4. 대시보드 쪽 확인 목록

1. 모델 식별자가 보이는 모든 곳(사건 목록·상세·필터·칩, 운영 화면 임계값, 분석가 판정 집계)이 표시 이름으로 바뀌었는가.
2. 수집 구간 선택·표시가 표시 이름으로 바뀌고, 원래 ID는 툴팁에 있는가.
3. `lab-20261201`이 시연 화면에서 보이지 않는가.
